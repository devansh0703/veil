Private payment rails for the agent economy

Agents can pay for anything. On a public chain, everyone can watch them do it.

x402 gave agents a way to pay for an API call without a human and without an account. It left the amount, the counterparty and the pattern on a public ledger. Veil closes that gap with two real primitives — not a mixer, not a promise.

What the mechanism actually is

01 · Confidential Balances
Token-2022's native extension. The transfer amount and both balances are stored as ElGamal ciphertext. Proofs are generated client-side and verified on chain, so a validator still knows the transfer is valid and non-inflationary — it just cannot read the number. No ZK circuit was written for this. The chain's own extension does it.
02 · Verify, then offer
Before quoting a price the server checks that the mint carries the extension and that the destination account accepts confidential credits. If it cannot check, it refuses with VEIL-CONF-003 rather than quoting. A settlement offer is a promise, and this is where the promise is made conditional on evidence. The source of that evidence is published at /.well-known/veil as privacySource, so a deployment that declared it instead of reading it cannot pass for one that read it.
03 · One-time addresses
Each paid call derives a fresh recipient account from the merchant's alias, used once. Confidential Balances hides the amount; this hides the edge. Together they defeat the two cheap deanonymisation attacks: reading the figure, and counting the recurrence.
04 · The refusal
When the preconditions cannot be satisfied or cannot be checked, the server returns a specific code — VEIL-CONF-001 through 005 — and no price. It never downgrades to a public transfer, because a merchant who believed an amount was hidden while it sat in the clear has been actively misled. The merchant ledger renders those codes as rows, so a refusal is visible rather than quietly absent. A privacy claim is worth nothing the moment the product lies to keep it looking true.

Encrypted until the holder decrypts — the mechanism, drawn

Public view writes a redaction bar over every amount. Lift view removes them, staggered — the same thing that happens the moment the merchant's key decrypts its own recipient ciphertext. It is not decoration: the toggle is how Veil states the boundary between the ledger's reader and everyone else, and how it proves the number was there the entire time.

Lifting the bars is a demonstration, not a back door. The auditor key is a single global key per mint — it cannot be the merchant's reconciliation path, and Veil does not pretend otherwise. Merchant reconciliation decrypts the merchant's own ciphertext.

Drop-in, because x402 is already the standard

Veil is a conformant x402 facilitator that speaks a confidential transfer instead of a plain one. A merchant that already accepts x402 adds a settlement address and nothing else. If the buyer's token account is not confidential, the facilitator refuses with a machine-readable reason instead of quietly settling in public.

merchant · settlement config3 lines
settlement = veil.facilitator(
  alias: "feedmarket.veil",
  confidential: true )
facilitator · refusal bodyHTTP 402
status  402
code    VEIL-CONF-003
reason  "confidential extension absent"
action  "configure account, then retry"

Refusing is a feature. A facilitator that accepts a non-confidential account still "works" and silently leaks the amount it promised to hide — which is worse than failing. Read the full 402 body →

The rail is deployed, not diagrammed. The mint, the one-time pool and two complete payment flows are confirmed on both clusters, and every row below links to the transaction that proves it — the operator's own end-to-end run, and an independent payer holding nothing but its own key.

Devnet · the same, from a cold start
Mint and pool created in one session from an untouched 5 SOL for 0.011 SOL, then both flows ran end to end. /verify 260 ms → /settle 916 ms, and the merchant seat decrypted 49000 with the merchant key alone. operator transfer → · independent-payer settle →
Hosted — the rail in public
Merchant server and facilitator behind one HTTPS origin, free tier, no card: veil-sable-five.vercel.app. A payment settled through the hosted facilitator — /verify → /settle against the public URL, merchant decrypted 49000. hosted settlement →
The deployer is not in a payment
Deployment paid the one-time rent; after that the deployer's key signs nothing. The payer signs its own transfer, the facilitator co-signs the fee, the merchant alone decrypts the amount. Reproduce either cluster with npm run pay:live -- --apply — the three proofs are generated on the machine that pays.
