## Affected Pages/Routes

- `/` (landing) — claim, two-window demo embed, verify-it-yourself link. Test that the video loads and the verify link resolves.
- `/dashboard` — merchant reconciliation: settled total, per-payment rows (alias, amount, time, state), per-vendor breakdown, CSV export.
- `GET /payment/:pid` (facilitator serve gate) — public, unauthenticated, keyed by payment id.
- `GET /ledger` + `GET /ledger/export` (merchant-scoped) — private financial data.

## Key Interactions to Verify

- Merchant adds one line to a stock x402 handler; the next 402 becomes confidential on-chain.
- Agent `veilFetch(url)` pays and receives the resource; price is checked against budget before paying.
- After payment, the Solana explorer shows the receiving address with an **unreadable amount** and **no prior history**.
- Merchant dashboard decrypts its own received amounts (recipient ciphertext) and shows the true total.
- CSV export totals match the on-chain decryption exactly ("reconciles to the cent").

## Edge Cases

- Duplicate/retried request for the same payment id → served once, second returns the cached decision.
- Two concurrent verifications of the same payment id → exactly one serve (atomic claim).
- Payment lands in a **pending** balance → dashboard shows pending vs available distinctly.
- Pool exhausted → payment refuses; must never fall back to a public account.
- Empty ledger (zero payments) → explicit empty state.
- Decrypt error / rotated key version → row flagged unverifiable, never a wrong total.
- RPC 429 mid-demo → backoff and complete, or bounded fail; no silent stall.
- Merchant process restarts between payment and serve → payment credited, "paid, not delivered" row, retry serves once.
- Landing page on a phone (judges open the URL on mobile).
- Verify-it-yourself link on a fresh browser with no local setup.

## Critical Paths

1. **Confidentiality assertion** — read the receiving account, assert the confidential extension is present and the amount is not plaintext; refuse to serve otherwise.
2. **Hostile QA** — force the public-transfer path; the product must REFUSE and the assertion-failure counter must go to 1.
3. **Derivation agreement** — agent and merchant derive the same one-time address for the same inputs, over many random inputs.
4. **Settlement idempotency** — two concurrent verifies of one payment id produce exactly one serve.
5. **Pool pre-configuration** — every assigned account has `allow_confidential_credits=true` and `allow_non_confidential_credits=false`.
6. **Demo smoke** — over 50 real devnet payments: exactly 50 distinct counterparty addresses, 0 publicly readable amounts.
